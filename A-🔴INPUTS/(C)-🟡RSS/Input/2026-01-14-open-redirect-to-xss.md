> 本文讲述了一名漏洞赏金猎人如何将常被忽视的开放重定向（Open Redirect）漏洞成功升级为跨站脚本（XSS）漏洞并获得奖励的过程。作者在目标网站登录流程中发现未严格校验的`redirect_url`参数，通过URL编码和路径混淆绕过基础过滤，实现外部跳转；进一步尝试`javascript:alert(1)` payload，发现该参数被直接用于`window.location`赋值，从而触发同源JavaScript执行，达成XSS。文章还提供了针对此类漏洞的实战技巧，如使用Google dork搜索隐藏参数、优先测试`javascript:`协议等。

<figure><img alt="" src="https://cdn-images-1.medium.com/max/789/1*VC_Ol0YnIDj_79VJkuhQJA.png" /></figure><p>Many bug bounty hunters overlook <strong>Open Redirect</strong> vulnerabilities, thinking they are “just a phishing vector.” But what if I told you that a redirect parameter could lead to full-blown Javascript execution? Today, I will share my journey of how I discovered an Open Redirect and escalated it to a rewarding XSS vulnerability.</p><h3>What is Open Redirect?</h3><p>Open Redirect occurs when an application takes user-provided input and uses it to redirect the user to another page without proper validation. Attackers often use this to make malicious links look like they belong to a trusted domain.</p><p><a href="https://medium.com/@xelcezeri/3a579bf64ed2?source=friends_link&amp;sk=ec350bf83180cb28bc045cc9a1811e17">Friend Link</a></p><h3>The Discovery: Hunting for Parameters</h3><p>While exploring my target (redacted.com), I focused on the login flow. I noticed a common parameter in the URL: <a href="https://redacted.com/login?redirect_url=/my-account">https://redacted.com/login?redirect_url=/my-account</a></p><p>This parameter tells the server where to send the user after a successful login. I immediately tested the obvious: <a href="https://redacted.com/login?redirect_url=https://evil.com">https://redacted.com/login?redirect_url=https://evil.com</a></p><p><strong>The Result:</strong> Blocked! The developers had implemented a basic filter.</p><h3>The Bypass Strategy</h3><p>I didn’t give up. I tried several bypass techniques using slashes and encoding:</p><ul><li>///evil.com</li><li>/\/evil.com</li><li>\/\/evil.com</li></ul><p>One of these variations worked perfectly. After logging in, the browser redirected me straight to my external malicious site.</p><h3>The Escalation: Turning Redirect into XSS</h3><p>An Open Redirect is good, but XSS is better. I wondered if the redirect_url parameter supported the javascript: URI scheme.</p><p>I crafted the following payload: <a href="https://redacted.com/login?redirect_url=javascript:alert(document.cookie)">https://redacted.com/login?redirect_url=javascript:alert(1)</a></p><p><strong>The Moment of Truth:</strong> I logged into the application. Instead of being redirected to a new page, the browser executed my JavaScript code on the redacted.com domain. <strong>XSS Triggered!</strong></p><figure><img alt="" src="https://cdn-images-1.medium.com/max/278/1*pAQnyafB7hwhfJgvuaWicw.png" /></figure><h3>Pro Tips for Hunters</h3><ul><li><strong>Dorking:</strong> Use dorks like site:target.com inurl:url= to find hidden redirect parameters.</li><li><strong>Payloads:</strong> Always try javascript:alert(1) on redirect parameters. If the application uses the input in a window.location assignment, you have a high chance of success.</li></ul><p><strong>Result:</strong> Reported to the team and rewarded with a <strong>$$ bounty</strong>!</p><h3>Stay Connected</h3><ul><li><strong>X (Twitter):</strong> <a href="https://x.com/xelcezeri">@xelcezeri</a></li><li><a href="https://www.linkedin.com/in/xsametyigit/"><strong>LinkedIn:</strong> Samet Yiğit</a></li></ul><img alt="" height="1" src="https://medium.com/_/stat?event=post.clientViewed&amp;referrerSource=full_rss&amp;postId=3a579bf64ed2" width="1" />
