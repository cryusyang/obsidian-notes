<h3>How a Newline Injection in Folder Names Broke Access Revocation</h3><p>Sometimes the smallest input validation issues can snowball into serious business logic flaws. This bug is a great example — a simple newline character (%0a) in a folder name was enough to <strong>block owners from revoking access rights</strong>, leaving attackers stuck with elevated privileges.</p><figure><img alt="" src="https://cdn-images-1.medium.com/max/1024/1*oNnzjIRzvhgVeSEeCNdlkw.png" /></figure><h3>Understanding the Target</h3><p>CollabSpace(pseudo name for private bbp product) is a cloud-based platform for project collaboration, offering resource sharing, folder management, and granular access controls. Owners can share resources and grant collaborators rights such as <em>View</em>, <em>Edit</em>, or <em>Transfer Edit Rights</em>.</p><p>To maintain control, project owners should always be able to <strong>revoke or update collaborator access</strong>. However, this restriction was bypassed by abusing folder naming logic.</p><h3>The Flaw: Newline Injection in Folder Names</h3><p>The vulnerability occurred because the backend failed to validate folder names properly. By creating a folder with a <strong>newline character (%0a) at the start of its name</strong>, the system broke critical permission workflows.</p><p>Here’s the malicious request:</p><blockquote>POST /api/v1/fs?path=&amp;rid=&lt;resource_id&gt;&amp;dirname=%0aattackerfolder HTTP/2<br />Host: collabspace.com</blockquote><p>This created a folder with a malformed name that disrupted backend path handling.</p><h3>Steps to Reproduce</h3><ol><li><strong>Owner grants Transfer Edit Rights</strong> to a collaborator (attacker).</li><li><strong>Attacker(editor user) creates a folder</strong> with %0a at the start of the folder name.</li><li><strong>Owner attempts to revoke rights or delete the folder</strong></li></ol><ul><li>This action fails due to backend errors triggered by the malformed folder name.</li></ul><p>Result: The attacker retains their access indefinitely.</p><h3>Impact</h3><ul><li><strong>Persistent Access:</strong> Attackers could keep edit rights permanently.</li><li><strong>Denial of Control:</strong> Owners couldn’t revoke access or delete malicious folders.</li><li><strong>Workflow Disruption:</strong> Ownership revocation logic was effectively broken.</li><li><strong>Potential Abuse:</strong> Attackers could create multiple such folders, locking down workspaces.</li></ul><h3>Bounty &amp; Program Response</h3><ul><li><strong>Reported:</strong> July 7, 2025</li><li><strong>Triaged:</strong> July 9, 2025</li><li><strong>Severity:</strong> High (8.5) → downgraded to Medium (6.0)</li><li><strong>Bounty Awarded:</strong> $500 + $250 bonus</li></ul><figure><img alt="" src="https://cdn-images-1.medium.com/max/294/1*RSOVa1nF7bBq6_-Hicep0w.png" /></figure><p>The program acknowledged that although the confidentiality impact was low, this was a <strong>well-crafted and creative finding</strong> that broke ownership workflows, which earned a bonus.</p><h3>Key Takeaways</h3><ul><li>Always check user inputs, including <strong>folder and file names</strong>.</li><li>Small oversights in <strong>business logic</strong> can cause <strong>privilege persistence</strong> issues.</li><li>Test boundaries with unusual inputs: newlines, nulls, special characters often reveal flaws.</li><li>Even if a bug seems minor, well-documented reports can lead to <strong>bonus rewards</strong>.</li></ul><h3>Conclusion</h3><p>This was a unique case where a simple <strong>newline injection</strong> caused project owners to lose control over collaborator access.
