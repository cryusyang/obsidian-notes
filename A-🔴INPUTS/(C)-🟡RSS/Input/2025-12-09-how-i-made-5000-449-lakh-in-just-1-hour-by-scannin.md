<p>Hi everyone,<br />It’s been a while since I published something useful, so here’s a quick write-up of how I made $5,000 in about <strong>one hour</strong> of focused recon. Yes, this is literally just from analyzing JavaScript files nothing advanced, no fuzzing, no complex exploitation.</p><figure><img alt="" src="https://cdn-images-1.medium.com/max/1024/1*apk6PMWzKAK25KuBb_9flw.png" /></figure><p>Most people know that JS files can leak secrets, but very few bug hunters take the time to look at the <em>historical</em> versions. That’s where the real gold often hides.</p><p>This happened on a private program. The scope was tiny just the main staging web app, no wildcard, no subdomains. While checking the page source, I saw they weren’t using runtime-injected environment variables. Instead, they were shipping old-style bundled JS files like main.js, app.js, etc.</p><p>That instantly told me:<br /><strong>If these bundles existed for many years, older versions might contain secrets.</strong></p><h3>Inspired by Frans Rosen’s Method</h3><p>I remembered Frans Rosen’s BSides Ahmedabad talk where he said he even checks documentation snapshots from different years to see how things evolved. That reminded me that developers often fix issues “visually” but forget to revoke old keys.</p><p>So I pulled the current JavaScript bundles and then checked their older versions using Web Archive snapshots from 2020 onward.</p><p>Here’s what I discovered:</p><p><strong>2022 snapshot:</strong> contained exposed API keys<br /><strong>2023 snapshot:</strong> keys removed<br /><strong>Today:</strong> keys still active and usable</p><p>This is extremely common developers remove secrets from the frontend but forget to rotate or revoke them.</p><p>With a couple of simple cURL requests, I could immediately pull sensitive production data, including PII. That single bug alone earned <strong>$3,500</strong>.</p><p>Total time spent so far: <strong>about 25 minutes</strong>.</p><figure><img alt="" src="https://cdn-images-1.medium.com/max/384/1*0XpLGOsoIoph75HZdKpL3Q.png" /></figure><h4>Next Step: Mining for More JS Files</h4><p>After confirming the first bug, I used gau, waybackurls, and subjs to gather every JS file historically associated with the domain.</p><p>Some of those archived JS files were no longer present on the live app but were still accessible through CDNs or static storage. A few contained additional sensitive data and misconfigurations.</p><p>Those findings resulted in more payouts, bringing the total up to:</p><p><strong>$5,000 in around 1 hour.</strong></p><h4>Tools I Used</h4><p><strong>Web Archive</strong><br />To browse historical JS bundles and compare changes year by year.</p><p><strong>Waybackurls &amp; Gau</strong><br />To automatically pull every JavaScript file archived for the domain.</p><p><strong>Subjs</strong><br />To extract additional JS endpoints from live and historical pages.</p><p><strong>JS Miner</strong><br />Great for scanning large JS bundles for secrets. However, the key finding that earned $3,500 wasn’t detected by JS Miner, so…</p><p><strong>Manual Burp Search</strong><br />I always keep the habit of searching manually inside JS files using Burp’s search feature, especially with regex. I used this regex pattern:<br /><a href="https://github.com/Lu3ky13/Search-for-all-leaked-keys-secrets-using-one-regex-">https://github.com/Lu3ky13/Search-for-all-leaked-keys-secrets-using-one-regex-</a></p><p>Manual review paid off literally.</p><h4>Lessons Learned</h4><p>Automated tools are great for coverage, but they will always miss things. Important JS files should be reviewed by hand because developers often rely on “security by cleaning the current version” but forget to revoke old keys, rotate secrets, or check what their assets looked like 1–3 years ago.</p><p>Historical JS recon is still incredibly underrated.<br />Most bug hunters only look at what’s currently served by the application, but companies often leave a trail of sensitive artifacts behind on the internet. If those keys are still valid, the impact can be huge.</p><p>Thank you &amp; Follow: <a href="https://x.com/tabaahi_">https://x.com/tabaahi_</a></p><img alt="" height="1" src="https://medium.com/_/stat?event=post.clientViewed&amp;referrerSource=full_rss&amp;postId=18428e9184d9" width="1" />
