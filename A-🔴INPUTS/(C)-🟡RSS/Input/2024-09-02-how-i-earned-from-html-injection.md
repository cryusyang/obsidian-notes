<figure><img alt="" src="https://cdn-images-1.medium.com/max/1024/1*HDoP-b1ygbSTGkIDcEckkw.png" /></figure><h3>Introduction :</h3><p><strong>Hello, everyone!</strong> I’m Mo Salah, a beginner bug hunter with a passion for learning and exploring cybersecurity. This is my first blog post, so I appreciate your understanding if I make any mistakes. Today, I’ll be discussing a recent discovery I made — a bug involving HTML injection. Let’s dive into the details!</p><blockquote><strong>What is HTML Injection?</strong></blockquote><p>HTML Injection is a type of security vulnerability that occurs when an application allows user input to be included in the output without proper validation, sanitization, or escaping. This vulnerability enables attackers to inject arbitrary HTML code into a web page viewed by other users. The injected code can include JavaScript, CSS, or any other code that the browser can execute. The impact of HTML injection can range from minor nuisances to significant security breaches, including session hijacking, phishing attacks, and spreading malware.</p><blockquote>Let’s get started:</blockquote><p>I found the bug in the search feature of the application. When I typed a query that produced search results, the input was displayed both on the webpage and in the source code. However, if the search query didn’t yield any results, the input wasn’t visible on the webpage but was still present in the source code.</p><p>When I entered Mo&lt;h2&gt; in the search field, it appeared in nine different places within the source code. Out of these, eight instances were properly filtered to prevent any unwanted behavior. However, one instance was injected into a &lt;script&gt; tag without any filtering, which poses a significant security risk due to the potential for HTML injection.</p><figure><img alt="" src="https://cdn-images-1.medium.com/max/277/1*nKWriIQuXtJ5QJAqVlYgvA.png" /></figure><p>Unfortunately, I wasn’t able to inject HTML when the search query returned results because all instances were properly filtered. However, if the search query didn’t return any results, there was one unfiltered location where the input was vulnerable. To exploit this, I needed to ensure that the search query didn’t produce any results.</p><p>The vulnerable spot was within a &lt;script&gt; tag, so to exploit it, I needed to close the script tag and inject my HTML code. When I attempted to close the script tag and add HTML, such as &lt;h1&gt;Mo Salah&lt;/h1&gt;, it did not render on the webpage as expected. Despite trying various HTML injections, none of the code appeared on the page—it was only visible in the source code.</p><figure><img alt="" src="https://cdn-images-1.medium.com/max/407/1*GDSpRP_tDWu5qTNC-SZw6w.png" /><figcaption>value reflected in source code</figcaption></figure><figure><img alt="" src="https://cdn-images-1.medium.com/max/1024/1*yRJFVlFNeXq7JmXTM6P7IA.png" /><figcaption>value not reflected on web page</figcaption></figure><p>I attempted to inject &lt;!-- to comment out the entire code block, but my attempt was interrupted by an existing comment left by the developer, which effectively broke my comment.</p><p>After two hours of trying different methods to render HTML on the webpage, I noticed something interesting: when I injected a &lt;style&gt; tag, the entire content of the page was hidden, resulting in a completely blank webpage</p><figure><img alt="" src="https://cdn-images-1.medium.com/max/1024/1*DagXEiaLY6-ZyNLAzt6CzA.png" /><figcaption>Blank page</figcaption></figure><p>This occurred because when I injected a &lt;style&gt; tag, everything following it was treated as CSS code. Since the injected content wasn't valid CSS, it caused the browser to fail in rendering any of the page's content, resulting in a blank page.</p><p>After successfully making the webpage blank with the &lt;style&gt; injection, I crafted a payload: &lt;/script&gt;&lt;h1&gt;Mo Salah&lt;/h1&gt;&lt;style&gt;. This payload successfully closed the vulnerable &lt;script&gt; tag and injected the HTML code. As a result, &quot;Mo Salah&quot; was correctly rendered on the page as an &lt;h1&gt; header, and all subsequent content after the &lt;style&gt; tag was effectively removed from the page.</p><figure><img alt="" src="https://cdn-images-1.medium.com/max/1024/1*bBB4mwY0VwOoGssrWhZzzw.png" /><figcaption>HTML Rendering</figcaption></figure><p>Let’s create a simple page.</p><figure><img alt="" src="https://cdn-images-1.medium.com/max/1024/1*bOahgLTadjL1H9AlHwakRA.png" /><figcaption>Final POC</figcaption></figure><p>After submitting the report, I received the bounty the next day.</p><figure><img alt="" src="https://cdn-images-1.medium.com/max/524/1*s60IqqXILE4edhJIpf0iOA.jpeg" /></figure><p>Please let me know if there is anything more I can help with</p><blockquote>X: <a href="https://x.com/0x_MoSalah">https://x.com/0x_MoSalah</a></blockquote><blockquote>LinkedIn: <a href="https://www.linkedin.com/in/mo-salah-744a67217/">https://www.linkedin.com/in/mo-salah-744a67217/</a></blockquote><p>Thank you for taking the time to read this.</p><img alt="" height="1" src="https://medium.com/_/stat?event=post.clientViewed&amp;referrerSource=full_rss&amp;postId=7b4da98ab6e3" width="1" />
