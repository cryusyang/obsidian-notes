> [!example] AI 摘要
> 本文介绍了一种绕过严格CSP防护的SVG滥用技术，通过上传恶意SVG文件并结合宽松配置的OAuth重定向URI，实现无需XSS的账户接管。核心在于利用SVG的`<foreignObject>`嵌入HTML，配合`referrer="unsafe-url"`和`meta refresh`重定向，将OAuth令牌泄露至攻击者服务器。该攻击依赖两个关键原语：可托管于目标域名的SVG上传，以及OAuth允许任意子路径重定向的缺陷。最后，文章还提及该技术可扩展用于红队钓鱼场景。

<h2>
 <span>
  SVG 滥用：无需 XSS 的账户接管
 </span>
</h2>
<p>
 <span>
  SVG 上传是一个非常有趣的攻击面！大多数渗透测试人员都会检查 XSS，但如果内容安全策略（CSP）被设置为
 </span>
 <code>
  <span>
   <span>
    script
   </span>
  </span>
  <span>
   <span>
    -
   </span>
  </span>
  <span>
   <span>
    src
   </span>
  </span>
  <span>
   <span>
    :
   </span>
  </span>
  <span>
   <span>
    none
   </span>
  </span>
 </code>
 <span>
  怎么办？
 </span>
</p>
<p>
 <span>
  并非无路可走！本文将介绍一种技术：通过将 SVG 鲜为人知的 HTML 嵌入功能与宽松的 OAuth 重定向配置相结合，从而实现账户接管。
 </span>
</p>
<p>
 <span>
  文章末尾还展示了另一个加分向量，它非常适合在红队或渗透测试任务中用于网络钓鱼攻击！
 </span>
</p>
<hr />
<h2>
 <span>
  攻击原语 (The Primitives)
 </span>
</h2>
<h3>
 <span>
  原语 1：SVG 上传
 </span>
</h3>
<p>
 <span>
  这个原语高度依赖于目标。目标是找到几乎任何文件上传的机会。在测试中，最常见的上传位置是用户账户的个人资料图片上传。
 </span>
</p>
<p>
 <span>
  应用程序通常在客户端实施文件类型验证，或者在服务器端仅检查
 </span>
 <code>
  <span>
   <span>
    Content
   </span>
  </span>
  <span>
   <span>
    -
   </span>
  </span>
  <span>
   <span>
    Type
   </span>
  </span>
 </code>
 <span>
  标头，而不是检查文件的幻数（Magic Bytes）。SVG 可能会在客户端被拦截。我遇到的一个真实案例是：服务器强制要求
 </span>
 <code>
  <span>
   <span>
    Content
   </span>
  </span>
  <span>
   <span>
    -
   </span>
  </span>
  <span>
   <span>
    Type
   </span>
  </span>
 </code>
 <span>
  为
 </span>
 <code>
  <span>
   <span>
    image
   </span>
  </span>
  <span>
   <span>
    /*
   </span>
  </span>
 </code>
 <span>
  ，但在客户端屏蔽了 SVG。
 </span>
</p>
<p>
 <span>
  为什么？因为图像通常被认为是无害的。然而，这种宽松的 content-type 验证允许我通过拦截代理（如 Burp Suite）将
 </span>
 <code>
  <span>
   <span>
    Content
   </span>
  </span>
  <span>
   <span>
    -
   </span>
  </span>
  <span>
   <span>
    Type
   </span>
  </span>
 </code>
 <span>
  修改为
 </span>
 <code>
  <span>
   <span>
    image
   </span>
  </span>
  <span>
   <span>
    /
   </span>
  </span>
  <span>
   <span>
    svg
   </span>
  </span>
  <span>
   <span>
    +
   </span>
  </span>
  <span>
   <span>
    xml
   </span>
  </span>
 </code>
 <span>
  ，从而成功走私 SVG 文件。
 </span>
</p>
<p>

  </span>

  </span>
  <span>
   <span>
    -
   </span>
  </span>
  <span>
   <span>
    Type
   </span>
  </span>
 </code>
 <span>
  标头：
 </span>
</p>

 <span>
  如果服务器接受了该文件，且该文件是从
 </span>
 <strong style="font-weight: bold; color: rgb(0, 0, 0); margin-top: 0px;">
  <span>
   主应用域名
  </span>
 </strong>
 <span>
  （而非 CDN 或 S3 存储桶）提供的，你就获得了第一个原语。
 </span>
</p>
<h3>
 <span>
  原语 2：OAuth 重定向 URI (Redirect URI)
 </span>
</h3>
<p>
 <span>
  OAuth 实现经常被错误配置，导致其接受任何与域名匹配的重定向 URI，而不是精确的字符串匹配。在这种情况下，攻击者可以将
 </span>
 <code>
  <span>
   <span>
    redirect_uri
   </span>
  </span>
 </code>
 <span>
  设置为目标域名下的任何路径，包括他们可以控制内容的路径。
 </span>
</p>
<p>
 <span>
  例如，第一个原语生成的 URL 可能是：
 </span>
</p>
<blockquote>
 <p style="margin: 0px; padding: 0px; font-size: 14px; white-space: pre-line; line-height: 30px; color: rgb(74, 74, 74);">
  <code>
   <span>
    <span>
     https
    </span>
   </span>
   <span>
    <span>
     :
    </span>
   </span>
   <span>
    <span>
     //example.com/uploads/avatars/attacker-profile.svg
    </span>
   </span>
  </code>
 </p>
</blockquote>
<p>
 <span>
  如果应用程序只检查
 </span>
 <code>
  <span>
   <span>
    redirect_uri
   </span>
  </span>
 </code>
 <span>
  中是否包含
 </span>
 <code>
  <span>
   <span>
    example
   </span>
  </span>
  <span>
   <span>
    .
   </span>
  </span>
  <span>
   <span>
    com
   </span>
  </span>
 </code>
 <span>
  （例如匹配
 </span>
 <code>
  <span>
   <span>
    https
   </span>
  </span>
  <span>
   <span>
    :
   </span>
  </span>
  <span>
   <span>
    //*.example.com/*
   </span>
  </span>
 </code>
 <span>
  ），那么你就拥有了第二个原语。
 </span>
</p>
<p>
 <span>
  OAuth 授权码（Code）或令牌（Token）会在重定向发生前作为查询参数附加到该 URL，并显示在浏览器的地址栏中。
 </span>
</p>
<hr />
<h2>
 <span>
  漏洞利用链
 </span>
</h2>
<h3>
 <span>
  第一步：构建 SVG 有效负载
 </span>
</h3>
<p>
 <span>
  SVG 支持通过
 </span>
 <code>
  <span>
   <span>
    &lt;foreignObject&gt;
   </span>
  </span>
 </code>
 <span>
  元素嵌入任意 HTML。这通常用于富文本渲染，但它也允许注入
 </span>
 <code>
  <span>
   <span>
    &lt;meta&gt;
   </span>
  </span>
 </code>
 <span>
  标签。
 </span>
</p>
<p>
 <strong style="font-weight: bold; color: rgb(0, 0, 0); margin-top: 0px;">
  <span>
   为什么这很重要：
  </span>
 </strong>
 <span>
  你可以在托管于目标域名的 SVG 内部将
 </span>
 <code>
  <span>
   <span>
    Referrer
   </span>
  </span>
  <span>
   <span>
    -
   </span>
  </span>
  <span>
   <span>
    Policy
   </span>
  </span>
 </code>
 <span>
  设置为
 </span>
 <code>
  <span>
   <span>
    unsafe
   </span>
  </span>
  <span>
   <span>
    -
   </span>
  </span>
  <span>
   <span>
    url
   </span>
  </span>
 </code>
 <span>
  ，然后通过另一个带有浏览器刷新的
 </span>
 <code>
  <span>
   <span>
    &lt;meta&gt;
   </span>
  </span>
 </code>
 <span>
  标签立即重定向到你的外部收集服务器。浏览器将在
 </span>
 <code>
  <span>
   <span>
    Referer
   </span>
  </span>
 </code>
 <span>
  标头中发送完整的 URL，包括查询字符串中的 OAuth 令牌。
 </span>
</p>

<h3>
 <span>
  第二步：获取 Payload 的 URL
 </span>
</h3>
<p>
 <span>
  上传后，记录 SVG 所在的完整 URL。例如：
 </span>
</p>
<blockquote>
 <p style="margin: 0px; padding: 0px; font-size: 14px; white-space: pre-line; line-height: 30px; color: rgb(74, 74, 74);">
  <code>
   <span>
    <span>
     https
    </span>
   </span>
   <span>
    <span>
     :
    </span>
   </span>
   <span>
    <span>
     //example.com/uploads/avatars/a1b2c3.svg
    </span>
   </span>
  </code>
 </p>
</blockquote>
<p>
 <span>
  该 URL 必须无需身份验证即可访问，攻击才能针对任何用户生效。
 </span>
</p>
<h3>
 <span>
  第三步：构造 OAuth 链接
 </span>
</h3>
<p>
 <span>
  为目标的 OAuth 提供商（Google、Discord 等）构建一个授权 URL，并将你的 SVG URL 作为
 </span>
 <code>
  <span>
   <span>
    redirect_uri
   </span>
  </span>
 </code>
 <span>
  。
 </span>
</p>
<p>
 <span>
  只需将重定向参数更改为你的 SVG 位置，例如：
 </span>
</p>
<blockquote>

<h2>
 <span>
  为什么现代引用策略（Referrer Policy）在这里失效了？
 </span>
</h2>
<p>
 <span>
  默认情况下，现代浏览器应用
 </span>
 <code>
  <span>
   <span>
    strict
   </span>
  </span>
  <span>
   <span>
    -
   </span>
  </span>
  <span>
   <span>
    origin
   </span>
  </span>
  <span>
   <span>
    -
   </span>
  </span>
  <span>
   <span>
    when
   </span>
  </span>
  <span>
   <span>
    -
   </span>
  </span>
  <span>
   <span>
    cross
   </span>
  </span>
  <span>
   <span>
    -
   </span>
  </span>
  <span>
   <span>
    origin
   </span>
  </span>
 </code>
 <span>
  策略，这会在跨域导航时剥离查询参数和片段。在正常情况下，从
 </span>
 <code>
  <span>
   <span>
    example
   </span>
  </span>
  <span>
   <span>
    .
   </span>
  </span>
  <span>
   <span>
    com
   </span>
  </span>
  <span>
   <span>
    /
   </span>
  </span>
  <span>
   <span>
    page
   </span>
  </span>
  <span>
   <span>
    ?
   </span>
  </span>
  <span>
   <span>
    token
   </span>
  </span>
  <span>
   <span>
    =
   </span>
  </span>
  <span>
   <span>
    xyz
   </span>
  </span>
 </code>
 <span>
  重定向到
 </span>
 <code>
  <span>
   <span>
    attacker
   </span>
  </span>
  <span>
   <span>
    .
   </span>
  </span>
  <span>
   <span>
    com
   </span>
  </span>
 </code>
 <span>
  只会发送
 </span>
 <code>
  <span>
   <span>
    https
   </span>
  </span>
  <span>
   <span>
    :
   </span>
  </span>
  <span>
   <span>
    //example.com/
   </span>
  </span>
 </code>
 <span>
  作为 referrer。这是现代浏览器在 2020 年左右采用的变更。
 </span>
</p>
<p>
 <span>
  然而，SVG 的
 </span>
 <code>
  <span>
   <span>
    &lt;meta&gt;
   </span>
  </span>
 </code>
 <span>
  标签完全绕过了这一点。因为 SVG 是从
 </span>
 <code>
  <span>
   <span>
    example
   </span>
  </span>
  <span>
   <span>
    .
   </span>
  </span>
  <span>
   <span>
    com
   </span>
  </span>
 </code>
 <span>
  提供的，该 meta 标签的引用策略适用于该文档的出站导航，从而覆盖了浏览器默认设置或应用级别的策略。
 </span>
</p>

<h2>
 <span>
  防御措施
 </span>
</h2>
<ul class="list-paddingleft-1">
 <li style="margin-top: 6px !important; margin-right: 0px; margin-bottom: 0px; margin-left: 0px; padding: 0px;">
  <span style="font-size: 14px !important; color: rgb(74, 74, 74); margin-top: 0px; line-height: 22px;">
   <span style="font-size: 14px !important; color: rgb(74, 74, 74); margin-top: 0px; line-height: 22px;">
    <strong style="font-weight: bold; color: rgb(0, 0, 0); margin-top: 0px;">
     <span>
      SVG 上传：
     </span>
    </strong>
    <span>
     在服务器端通过
    </span>
    <strong style="font-weight: bold; color: rgb(0, 0, 0);">
     <span>
      幻数（Magic Bytes）
     </span>
    </strong>
    <span>
     拦截
    </span>
    <code>
     <span>
      <span>
       image
      </span>
     </span>
     <span>
      <span>
       /
      </span>
     </span>
     <span>
      <span>
       svg
      </span>
     </span>
     <span>
      <span>
       +
      </span>
     </span>
     <span>
      <span>
       xml
      </span>
     </span>
    </code>
    <span>
     ，而不仅仅是检查
    </span>
    <code>
     <span>
      <span>
       Content
      </span>
     </span>
     <span>
      <span>
       -
      </span>
     </span>
     <span>
      <span>
       Type
      </span>
     </span>
    </code>
    <span>
     标头；或者将所有用户上传的文件放在隔离的域（Isolated Origin）中提供服务。
    </span>
   </span>
  </span>
 </li>
 <li style="margin-top: 6px !important; margin-right: 0px; margin-bottom: 0px; margin-left: 0px; padding: 0px;">
  <span style="font-size: 14px !important; color: rgb(74, 74, 74); margin-top: 0px; line-height: 22px;">
   <span style="font-size: 14px !important; color: rgb(74, 74, 74); margin-top: 0px; line-height: 22px;">
    <strong style="font-weight: bold; color: rgb(0, 0, 0); margin-top: 0px;">
     <span>
      OAuth 重定向验证：
     </span>
    </strong>
    <span>
     强制执行
    </span>
    <code>
     <span>
      <span>
       redirect_uri
      </span>
     </span>
    </code>
    <span>
     的
    </span>
    <strong style="font-weight: bold; color: rgb(0, 0, 0);">
     <span>
      精确匹配
     </span>
    </strong>
    <span>
     验证；根据 RFC 6749，在域名上使用通配符路径匹配是一种错误配置。
    </span>
   </span>
  </span>
 </li>
 <li style="margin-top: 6px !important; margin-right: 0px; margin-bottom: 0px; margin-left: 0px; padding: 0px;">
  <span style="font-size: 14px !important; color: rgb(74, 74, 74); margin-top: 0px; line-height: 22px;">
   <span style="font-size: 14px !important; color: rgb(74, 74, 74); margin-top: 0px; line-height: 22px;">
    <strong style="font-weight: bold; color: rgb(0, 0, 0); margin-top: 0px;">
     <span>
      SVG 渲染：
     </span>
    </strong>
    <span>
     如果必须支持 SVG，在存储前通过服务器端净化（Sanitization）移除上传 SVG 中的
    </span>
    <code>
     <span>
      <span>
       &lt;foreignObject&gt;
      </span>
     </span>
    </code>
    <span>
     和
    </span>
    <code>
     <span>
      <span>
       &lt;meta&gt;
      </span>
     </span>
    </code>
    <span>
     元素。
    </span>
   </span>
  </span>
 </li>
</ul>
