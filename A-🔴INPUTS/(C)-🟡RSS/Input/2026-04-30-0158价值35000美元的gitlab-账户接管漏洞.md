> [!example] AI 摘要
> 安全研究员 asterion04 于2023年12月发现GitLab密码重置功能存在严重逻辑漏洞（CVSS 10.0），攻击者可通过篡改JSON请求，将单个邮箱参数替换为包含受害者与攻击者邮箱的数组，导致重置链接同时发送至双方邮箱，实现无交互式账户接管。漏洞根源在于后端未校验email参数类型，错误处理JSON数组并为所有地址生成相同令牌，属于参数注入与类型混淆组合缺陷。该漏洞影响所有使用邮箱登录的GitLab实例（含GitLab.com及自托管部署），已于2024年1月24日修复，GitLab为此支付35,000美元赏金。

<h2>
 <span>
  <span style="font-size: 20px;">
   概述
  </span>
 </span>
</h2>
<p>
 <span>
  <span style="font-size: 17px;">
   2023年12月，安全研究员
  </span>
 </span>
 <strong style="font-weight: 600;">
  <span>
   <span style="font-size: 17px;">
    asterion04
   </span>
  </span>
 </strong>
 <span>
  <span style="font-size: 17px;">
   向 GitLab 官方报告了一个严重的安全漏洞。该漏洞允许攻击者仅凭受害者的电子邮件地址，通过篡改密码重置请求的 JSON 结构，使重置链接同时发送至受害者和攻击者的邮箱。攻击者在获取链接后即可重置受害者密码，实现账户完全接管，且整个过程无需任何用户交互。
  </span>
 </span>
</p>
<p>
 <span>
  <br />
 </span>
</p>
<p>
 <span>
  <span style="font-size: 17px;">
   该漏洞最终被评定为
  </span>
 </span>
 <strong style="font-weight: 600;">
  <span>
   <span style="font-size: 17px;">
    严重（Critical，CVSS 10.0）
   </span>
  </span>
 </strong>
 <span>
  <span style="font-size: 17px;">
   ，GitLab 向研究员支付了总计
  </span>
 </span>
 <strong style="font-weight: 600;">
  <span>
   <span style="font-size: 17px;">
    35,000 美元
   </span>
  </span>
 </strong>
 <span>
  <span style="font-size: 17px;">
   的赏金（初始 1,000 美元 + 后续追加 34,000 美元）。漏洞已于 2024 年 1 月 24 日修复并公开披露。
  </span>
 </span>
</p>
<h2>
 <span>
  <span style="font-size: 20px;">
   漏洞复现步骤
  </span>
 </span>
</h2>
<ol class="list-paddingleft-1" start="1">
 <li>
  <p style="margin-right: 0px; margin-bottom: 0px; margin-left: 0px; margin-top: 0px !important;">
   <strong style="font-weight: 600;">
    <span>
     <span style="font-size: 17px;">
      访问密码重置页面
     </span>
    </span>
   </strong>
   <span>
    <br />
   </span>
   <span>
    <span style="font-size: 17px;">
     打开 GitLab 登录页面，点击“Forgot Your Password?”（忘记密码？）链接。
    </span>
   </span>
  </p>
 </li>
 <li style="margin-top: 6px;">
  <p style="margin-right: 0px; margin-bottom: 0px; margin-left: 0px; margin-top: 0px !important;">
   <strong style="font-weight: 600;">
    <span>
     <span style="font-size: 17px;">
      拦截并修改请求
     </span>
    </span>
   </strong>
   <span>
    <br />
   </span>
   <span>
    <span style="font-size: 17px;">
     输入受害者的邮箱地址（例如
    </span>
   </span>
   <code>
    <span>
     <span style="font-size: 17px;">
      victim@gmail.com
     </span>
    </span>
   </code>
   <span>
    <span style="font-size: 17px;">
     ），提交请求时使用 Burp Suite 拦截。
    </span>
   </span>
  </p>
 </li>
 <li style="margin-top: 6px;">
  <p style="margin-right: 0px; margin-bottom: 0px; margin-left: 0px; margin-top: 0px !important;">
   <strong style="font-weight: 600;">
    <span>
     <span style="font-size: 17px;">
      转换请求格式
     </span>
    </span>
   </strong>
   <span>
    <br />
   </span>
   <span>
    <span style="font-size: 17px;">
     在 Burp Suite 中右键点击 HTTP 编辑器，选择
    </span>
   </span>
   <code>
    <span>
     <span style="font-size: 17px;">
      Extensions -&gt; Content-Type Converter -&gt; Convert to JSON
     </span>
    </span>
   </code>
   <span>
    <span style="font-size: 17px;">
     。
    </span>
   </span>
   <span>
    <br />
   </span>
   <em>
    <span>
     <span style="font-size: 17px;">
      （需提前安装 Content-Type Converter 插件）
     </span>
    </span>
   </em>
  </p>
 </li>
</ol>
<p>
 <span>
  <span style="font-weight: bold;">
   4.篡改 JSON 结构，将转换后的 JSON 行：
  </span>
 </span>
</p>
<section>
 <ul class="code-snippet__line-index code-snippet__js">
  <li>
  </li>
 </ul>
 <pre class="code-snippet__js"><code><span><span>"user[email]"</span>:<span>"victim</span><span><span>@gmail</span></span><span>.com"</span></span></code></pre>
</section>
<p>
 <span>
  替换为以下数组格式：
 </span>
</p>
<section>
 <ul class="code-snippet__line-index code-snippet__js">
  <li>
  </li>
  <li>
  </li>
  <li>
  </li>
  <li>
  </li>
  <li>
  </li>
  <li>
  </li>
 </ul>
 <pre class="code-snippet__js"><code><span><span>"user"</span> {</span></code><code><span>    <span>"email"</span> [</span></code><code><span>        <span>"victim</span><span><span>@gmail</span></span><span>.com"</span>,</span></code><code><span>        <span>"attacker</span><span><span>@gmail</span></span><span>.com"</span></span></code><code><span>    ]</span></code><code><span>}</span></code></pre>
</section>
<section>
 <span>
  <span style="font-size: 17px; font-weight: bold;">
   5. 发送恶意请求，转发篡改后的请求。
  </span>
  <span style="font-size: 17px;">
   GitLab 后端会错误地将
  </span>
 </span>
 <code>
  <span>
   <span style="font-size: 17px;">
    email
   </span>
  </span>
 </code>
 <span>
  <span style="font-size: 17px;">
   字段解析为邮箱列表，并向其中所有地址发送相同的密码重置链接。
  </span>
 </span>
</section>
<p style="margin: 0px;">
 <span>
  <span style="font-size: 17px; font-weight: bold;">
   6. 接收重置链接并接管账户
  </span>
 </span>
 <span>
  <br />
 </span>
 <span>
  <span style="font-size: 17px;">
   攻击者在自己的邮箱（
  </span>
 </span>
 <code>
  <span>
   <span style="font-size: 17px;">
    attacker@gmail.com
   </span>
  </span>
 </code>
 <span>
  <span style="font-size: 17px;">
   ）中收到重置链接。点击链接后，即可为受害者账户设置新密码，随后使用新密码登录受害者账户。
  </span>
 </span>
</p>
<h2>
 <span>
  <br />
 </span>
</h2>
<h2>
 <span>
  <span style="font-size: 20px;">
   漏洞根源分析
  </span>
 </span>
</h2>
<p>
 <span>
  <span style="font-size: 17px;">
   该漏洞的根本原因在于 GitLab 密码重置功能对输入参数的解析逻辑存在缺陷：
  </span>
 </span>
</p>
<ul class="list-paddingleft-1">
 <li>
  <p style="margin: 0px;">
   <span>
    <span style="font-size: 17px;">
     后端开发者预期
    </span>
   </span>
   <code>
    <span>
     <span style="font-size: 17px;">
      user[email]
     </span>
    </span>
   </code>
   <span>
    <span style="font-size: 17px;">
     参数为字符串类型（即单个邮箱地址）。
    </span>
   </span>
  </p>
 </li>
 <li style="margin-top: 6px;">
  <p style="margin: 0px;">
   <span>
    <span style="font-size: 17px;">
     实际处理用户输入时，如果提交的是 JSON 数组，后端未能正确校验类型，错误地接受了数组形式。
    </span>
   </span>
  </p>
 </li>
 <li style="margin-top: 6px;">
  <p style="margin: 0px;">
   <span>
    <span style="font-size: 17px;">
     程序遍历数组内的所有邮箱地址，并为每个地址生成并发送相同的密码重置令牌，导致攻击者可同时获得有效链接。
    </span>
   </span>
  </p>
 </li>
</ul>
<p>
 <span>
  <span style="font-size: 17px;">
   这是一个典型的
  </span>
 </span>
 <strong style="font-weight: 600;">
  <span>
   <span style="font-size: 17px;">
    参数注入（Parameter Injection）
   </span>
  </span>
 </strong>
 <span>
  <span style="font-size: 17px;">
   与
  </span>
 </span>
 <strong style="font-weight: 600;">
  <span>
   <span style="font-size: 17px;">
    类型混淆（Type Confusion）
   </span>
  </span>
 </strong>
 <span>
  <span style="font-size: 17px;">
   组合漏洞，属于业务逻辑层面的严重缺陷。
  </span>
 </span>
</p>

  </p>
 </li>
</ul>
<h2>
 <span>
  <br />
 </span>
</h2>
<h2>
 <span>
  <span style="font-size: 20px;">
   修复方案
  </span>
 </span>
</h2>
<p>
 <span>
  <span style="font-size: 17px;">
   GitLab 在收到报告后迅速采取了以下修复措施：
  </span>
 </span>
</p>
<ul class="list-paddingleft-1">
 <li>
  <p style="margin: 0px;">
   <span>
    <span style="font-size: 17px;">
     对
    </span>
   </span>
   <code>
    <span>
     <span style="font-size: 17px;">
      email
     </span>
    </span>
   </code>
   <span>
    <span style="font-size: 17px;">
     参数添加严格的类型校验，拒绝数组或其他非字符串结构。
    </span>
   </span>
  </p>
 </li>
 <li style="margin-top: 6px;">
  <p style="margin: 0px;">
   <span>
    <span style="font-size: 17px;">
     确保密码重置请求中仅允许单个邮箱地址，且重置链接仅发送至该地址。
    </span>
   </span>
  </p>
 </li>
 <li style="margin-top: 6px;">
  <p style="margin: 0px;">
   <span>
    <span style="font-size: 17px;">
     增加针对参数混淆的防御机制，如使用强类型解析或白名单校验。
    </span>
   </span>
  </p>
 </li>
</ul>
