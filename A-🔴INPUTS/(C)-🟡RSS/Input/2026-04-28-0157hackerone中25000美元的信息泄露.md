> [!example] AI 摘要
> 安全研究员 avinash_ 在 2025 年 2 月发现 HackerOne 平台一个 CVSS 9.2 的严重信息泄露漏洞：因 Rails 框架从 6.1.7.9 升级至 7.1.5.1 后，哈希序列化行为变更导致 JSON 响应中重复键（符号 `:user` 和字符串 `"user"`）同时保留，意外暴露用户邮箱、OTP 备份码、手机号等高敏感数据。该漏洞仅在报告含摘要时触发，影响所有可访问的 `/reports/:id.json` 端点。HackerOne 在 90 分钟内确认并在两天内修复，移除了不安全的用户对象序列化逻辑；研究员获 25,000 美元赏金及 100 美元复测奖励。事件凸显底层依赖升级的风险及自动化测试（如 approvals gem）对重复键检测的盲区。

   </span>

 </span>
</h3>

 </span>
 <code>
  <span>

  </span>
 </code>
 <span>
  模板：

<section>
 <ul class="code-snippet__line-index code-snippet__js">

    </span>

   <span>
    <span>

 </span>

  </span>

 </span>
 <code>
  <span>

  </span>
 </code>
 <span>

 </span>
</p>

 <span>

 </span>
 <code>
  <span>
   "user"
  </span>
 </code>
 <span>

 </span>
 <strong style="font-weight: 600;">
  <span>
   敏感用户对象被意外暴露
  </span>
 </strong>
 <span>
  。
 </span>

<h2>
 <span>
  自动化测试为何未能发现？
 </span>
</h2>
<p>
 <span>
  HackerOne 使用
 </span>
 <code>
  <span>
   approvals
  </span>
 </code>
 <span>
  gem 进行 JSON 结构测试，典型代码为：
 </span>
</p>
<section>
 <ul class="code-snippet__line-index code-snippet__js">
  <li>
  </li>
 </ul>
 <pre class="code-snippet__js"><code><span><span>verify</span>(<span>format: :json</span>) { subject.<span>body</span> }</span></code></pre>
</section>
<section>
 <span>
  <span>
   该 gem 在比较前会
  </span>
 </span>
 <strong>
  <span>
   重新解析 JSON
  </span>
 </strong>
 <span>
  <span>
   。而在 Ruby 解析包含重复键的 JSON 时，默认行为是
  </span>
 </span>
 <strong>
  <span>
   只保留最后一个键的值
  </span>
 </strong>
 <span>
  <span>
   ：
  </span>
 </span>
</section>
<section>
 <ul class="code-snippet__line-index code-snippet__js">
  <li>
  </li>
  <li>
  </li>
 </ul>
 <pre class="code-snippet__js"><code><span><span>JSON</span>.parse(<span>'{"my_key":"my_value","my_key":"my_other_value"}'</span>)</span></code><code><span>=&gt; {<span>"my_key"</span>=&gt;<span>"my_other_value"</span>}   <span># 前一个值被丢弃</span></span></code></pre>
</section>
<section>
 <span>
  <span>
   因此，尽管实际 HTTP 响应体包含了重复键和敏感数据，但测试组件“看到”的仍然是旧版 Rails 的正常输出结构，
  </span>
 </span>
 <strong>
  <span>
   没有任何测试失败
  </span>
 </strong>
 <span>
  <span>
   ——漏洞就这样被安全测试体系漏过了。
  </span>
 </span>
</section>

   </code>
   <span>
    可能更安全，但指出根本问题在于数据结构设计不当，而非序列化方法本身。
   </span>

   <span>

   </span>
  </p>
