> 测试FinManageHub平台时，发现一个关键的越权访问漏洞：会计角色虽在UI中被禁止管理养老金计划，却可通过直接调用API成功删除所有私人养老金方案。该漏洞源于后端API未强制执行基于角色的访问控制（RBAC），导致前端限制被绕过，构成典型的不安全直接API调用（IDAC）问题。漏洞可能引发严重合规风险、员工养老金权益受损、审计日志缺失及法律追责。研究者因此获得500美元赏金，并强调必须在服务端强制授权、全面测试API、对敏感财务数据加强RBAC与审计保护。

<p>While testing the <strong>FinManageHub</strong> platform, I discovered a critical <strong>Broken Access Control</strong> vulnerability. An accountant role, which is restricted in the UI from managing pension schemes, was still able to remove all private pension schemes directly through an API call.</p><p>This bypassed role-based access control and could lead to severe compliance failures, financial misconfigurations, and legal liabilities. For this discovery, I was awarded a <strong>$300 bounty plus a $200 bonus</strong>.</p><figure><img alt="" src="https://cdn-images-1.medium.com/max/1024/1*UEJQ6GNU89eokE1OZSl0OA.png" /></figure><h3>Understanding the Target</h3><p>FinManageHub is a payroll and HR management SaaS platform that handles sensitive employee data such as salary, benefits, and pensions.</p><ul><li>Different roles (Admin, HR, Accountant, Employee) are assigned varying access levels.</li><li><strong>Accountants</strong> are usually restricted from directly modifying benefits like pensions.</li><li>Pension Scheme settings are critical, as removing them could disrupt contributions, violate labor laws, and cause compliance issues.</li></ul><p>While reviewing the platform’s flows, I noticed that pension management options were greyed out or inaccessible for accountants in the <strong>UI</strong>. This sparked my curiosity — what if the API endpoints behind these features weren’t enforcing the same restrictions?</p><h3>The Flaw: API Authorization Bypass</h3><p>The platform’s <strong>API layer did not enforce backend authorization checks consistently</strong>.</p><p>Even though the UI blocked accountants from removing pensions, sending a crafted <strong>POST request</strong> to the pension configuration endpoint worked successfully.</p><p>This revealed a classic <strong>Insecure Direct API Call (IDAC)</strong>:</p><blockquote>POST /payroll-v2/v1/public/jetlang/commands/save-company-action/915<br />Host: api.finmanagehub.com<br />Authorization: Bearer &lt;accountant-token&gt;<br />Content-Type: application/json</blockquote><blockquote>{<br /> “companyId”: “ — — your-companyid — — — — “,<br /> “absoluteMonth”: 104,<br /> “updates”: {<br /> “variables”: {<br /> “06.735”: { “104”: 0 }<br /> }<br /> },<br /> “updateInPastEnabled”: false<br />}</blockquote><p>Result: All private pension schemes were removed, despite the user lacking UI-level permissions.</p><h3>Impact</h3><ul><li><strong>Unauthorized Data Modification:</strong> Accountants could modify high-risk pension data.</li><li><strong>Compliance Risks:</strong> Removal of pension schemes could violate statutory obligations.</li><li><strong>Business Integrity:</strong> Employees may lose pension benefits unexpectedly.</li><li><strong>Audit Failures:</strong> Since changes bypass the UI, they may escape audit logs.</li></ul><p>This could have <strong>severe legal, financial, and trust implications</strong> for any organization using the platform.</p><h3>Timeline</h3><ul><li><strong>April 19, 2025</strong> — Report submitted.</li><li><strong>May 7, 2025</strong> — Triaged, severity adjusted (7.1 → 6.9). PR: H , I: H</li><li><strong>May 7, 2025</strong> — Rewarded <strong>$300 + $200 bonus</strong>.</li></ul><figure><img alt="" src="https://cdn-images-1.medium.com/max/1024/1*lB8hjIoATQHKFqUsZzF9-g.png" /></figure><h3>Key Takeaways</h3><ul><li><strong>Always test API endpoints directly.</strong> The UI may block actions, but the backend might still accept them.</li><li><strong>Role-based authorization must be enforced server-side.</strong> Relying only on front-end restrictions is dangerous.</li><li><strong>Compliance-related features require extra care.</strong> Financial and pension data must be protected with strict RBAC and audit logging.</li><li><strong>Revisit assumptions.</strong> Just because a role “shouldn’t” have access in the UI doesn’t mean the API agrees.</li></ul><p>✅ <strong>Connect and Engage</strong></p><p>💬 What’s your experience with finding <strong>access control bypasses in APIs</strong>?</p><p>Follow me on Twitter: <a href="https://twitter.com/a13h1_">@a13h1_</a></p><p>Keep clapping, commenting, and sharing your thoughts — your support motivates me to share more real bug bounty stories!</p><img alt="" height="1" src="https://medium.com/_/stat?event=post.clientViewed&amp;referrerSource=full_rss&amp;postId=7710dc6bbc58" width="1" /><hr /><p><a href="https://osintteam.blog/500-bac-bug-unauthorized-removal-of-private-pension-schemes-7710dc6bbc58">$500 BAC Bug: Unauthorized Removal of Private Pension Schemes</a> was originally published in <a href="https://osintteam.blog">OSINT Team</a> on Medium, where people are continuing the conversation by highlighting and responding to this story.</p>
