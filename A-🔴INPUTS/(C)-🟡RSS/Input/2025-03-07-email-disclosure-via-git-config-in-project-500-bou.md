<h3><strong>Email Disclosure via .git Config in project: </strong>$500 Bounty Bug</h3><p>Hey Everyone! I’m excited to share a vulnerability I recently discovered a <strong>sensitive information disclosure</strong> vulnerability in ExaHub that exposed <strong>project owners’ email addresses</strong> via the .git/config file. This issue allowed attackers to extract email addresses from <strong>public and shared projects</strong>, potentially leading to <strong>phishing attacks, social engineering, and unauthorized communication</strong>.For this discovery, I was awarded a <strong>$500 bounty</strong>. Let’s dive into how this bug worked, how I found it, and why it mattered.</p><figure><img alt="" src="https://cdn-images-1.medium.com/max/1024/1*kq_AiS7HemFDDJunBX1VHg.png" /></figure><h3>Understanding the Vulnerability</h3><p>ExaHub is a <strong>collaborative development platform for hulia-based projects</strong>, allowing users to <strong>host, share, and manage projects in the cloud</strong>. Every project maintains a <strong>Git repository</strong>, which includes configuration files that store user metadata, including email addresses.</p><p>A misconfiguration in exaHub’s access control policies allowed users to <strong>open and read</strong> the .git/config file of public or shared projects, inadvertently exposing the project owner’s email address.</p><h3>Steps to Reproduce</h3><p><strong>Find a Public or Shared Project:</strong></p><ul><li>Log in to ExaHub and navigate to a <strong>public project</strong> or a project shared with you.</li></ul><p><strong>Access the .git Folder:</strong></p><ul><li>Within the project directory, open the .git folder.</li></ul><p><strong>View the Config File:</strong></p><ul><li>Locate and open the .git/config file.</li></ul><p><strong>Extract the Email Address:</strong></p><ul><li>The owner’s email is visible under the [user] section:</li><li>[user] name = Project Owner email = owner@example.com</li></ul><p>This exposed email information could be <strong>harvested at scale</strong>, allowing attackers to build a list of ExaHub users for <strong>phishing attacks or unauthorized contact</strong>.</p><h3>Impact</h3><ul><li><strong>Sensitive Data Exposure:</strong> Attackers can extract email addresses of ExaHub users.</li><li><strong>Phishing &amp; Social Engineering:</strong> Exposed emails could be used for targeted attacks.</li><li><strong>Privacy Violation:</strong> Unauthorized users can retrieve private user information from shared project</li></ul><h3>Mitigation &amp; Recommendations</h3><p><strong>Restrict Access to .git Folders:</strong></p><ul><li>Implement access controls to prevent users from directly opening the .git directory.</li></ul><p><strong>Email Masking or Redaction:</strong></p><ul><li>Redact or replace emails in public .git/config files with generic placeholders.</li></ul><p><strong>User Education:</strong></p><ul><li>Warn users about the risks of exposing .git folders and encourage them to <strong>review permissions</strong>.</li></ul><p><strong>Git Ignore Rules:</strong></p><ul><li>Ensure that public projects <strong>automatically exclude</strong> the .git folder from visibility.</li></ul><h3>Timeline</h3><ul><li><strong>January 7, 2025:</strong> Report submitted to ExaHub.</li><li><strong>January 8, 2025:</strong> Acknowledged by ExaHub security team.</li><li><strong>January 20, 2025:</strong> Status updated to “Triaged” after validation.</li><li><strong>15 days later:</strong> $500 bounty awarded.</li></ul><figure><img alt="" src="https://cdn-images-1.medium.com/max/294/1*XEz23Rgm5kc1An5Ctq5c2Q.png" /></figure><h3>Key Takeaways for Finding Similar Vulnerabilities</h3><p><strong>Look for Misconfigured Git Repositories:</strong></p><ul><li>Public or shared .git folders often contain sensitive data like email addresses, credentials, or internal configurations.</li></ul><p><strong>Check Access Controls:</strong></p><ul><li>If a private configuration file is accessible in a public project, it could lead to information disclosure.</li></ul><p><strong>Inspect Metadata in Config Files:</strong></p><ul><li>Configuration files often store email addresses, API keys, or sensitive user details.</li></ul><p><strong>Use Automated Scanning Tools:</strong></p><ul><li>Tools like gitrob, truffleHog, or GitLeaks can help identify exposed secrets in Git repositories.</li></ul><p><strong>Manually Review File Contents:</strong></p><ul><li>Even if automated tools miss something, manually checking .git/config, .env, or .bash_history files can reveal valuable information.</li></ul><h3>Conclusion</h3><p>This vulnerability highlights the importance of <strong>restricting access to sensitive Git configuration files</strong>. Exposing emails via the .git/config file may seem like a minor issue, but it can be exploited for <strong>phishing, social engineering, and privacy breaches</strong>.</p><p>If you’re a developer or platform owner, always <strong>review Git configurations and enforce access restrictions</strong> to prevent unintended data leaks.</p><p>Until next time, happy hacking! 🚀</p><blockquote><strong><em>Connect and Engage</em></strong></blockquote><p>If you found this article informative, please share your feedback and insights in the comments section.
