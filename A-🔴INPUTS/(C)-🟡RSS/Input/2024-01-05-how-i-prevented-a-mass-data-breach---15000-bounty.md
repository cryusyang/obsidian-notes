> [!example] AI 摘要
> 安全研究员通过Google Dorking（如`site:privateprogram.com/webapp/`）和Wayback Machine发现目标子域`orders.privateprogram.com`存在严重IDOR漏洞：攻击者只需请求任意订单ID（如`/webapp/order/003163553`），即可获取对应认证Cookie，进而访问任意其他订单。该漏洞可批量泄露约300万用户的敏感信息，包括支付方式、合同PDF、收发货地址、联系方式及姓名等。漏洞于2023年7月19日报告，7月24日即获最高级别赏金并修复。

<p>In July 2023, I received an invite of a significant bug bounty program, with massive assets in-scope, my approach mirrored what I typically do when testing such extensive programs — searching for old endpoints using specific Google Dorks.</p><figure><img alt="" src="https://cdn-images-1.medium.com/max/1024/1*XwwAF9aY7yH8dIvrB8NbSg.png" /><figcaption>Dork used:<strong> site:privateprogram.com/webapp/</strong></figcaption></figure><p>After digging and experimenting with various dorks, I discovered a subdomain dedicated to storing user orders.</p><pre>https://orders.privateprogram.com/webapp/wcs/stores/servlet/OrderView?orderId=002233893</pre><p>I visited it, but of course, I got a forbidden error.</p><p>I wanted to see if there were more endpoints, so I saved that one for later and use the Wayback Machine.</p><figure><img alt="" src="https://cdn-images-1.medium.com/max/1024/1*3sr21ehIrwkbzmQLq3lPIQ.png" /><figcaption>http://web.archive.org/cdx/search/cdx?url=<strong>orders.privateprogram.com/webapp/</strong>*&amp;output=text&amp;fl=original&amp;collapse=urlkey&amp;from=-</figcaption></figure><p>Using the Wayback Machine. I found this new interesting endpoint:</p><pre>https://orders.privateprogram.com/webapp/wcs/stores/servlet/MailOid?orderId=003163553&amp;mailId=a1c156c4–6c4a-4bf9–9a17–2c5bvcdf6ec1</pre><p>I requested it and received a ‘200 Ok’ response, but it returned a blank page. Upon inspecting the response, I noticed the server was setting cookies each time I sent a request.</p><pre><br />HTTP/1.1 200 Ok<br /><br />.<br />..<br />...<br /><br />Set-Cookie:WC_PERSISTENT*=*************************<br />Set-Cookie:WC_AUTHENTICATION_*=***********************<br />Set-Cookie:WC_USERACTIVITY_*=*************************<br /><br />...<br />..<br />.</pre><p>If you are familiar with these cookies, you know these are actually authentication cookies.</p><p>So, I tried to see order 003163553 with those cookies</p><pre>https://orders.privateprogram.com/webapp/wcs/stores/servlet/OrderView?orderId=003163553</pre><p>And it worked! I gained access to that order. I speculated that the mailId might serve as a security key for accessing orders. To test this theory, I attempted the same exploit with another orderId I had found during earlier Google dorking (order 002233893, remember?) and managed to access it as well.</p><pre>https://orders.privateprogram.com/webapp/wcs/stores/servlet/OrderView?orderId=002233893</pre><p>While the mailId apparently tries to act as a security key, it works as the security key for all orders and will grant you access to any order as long as it is valid and present when requesting:</p><pre>https://orders.privateprogram.com/webapp/wcs/stores/servlet/MailOid?orderId=&lt;anyorder&gt;&amp;mailId=a1c156c4–6c4a-4bf9–9a17–2c5bvcdf6ec1</pre><p>To summarize, if I wanted to access, let’s say, orderId 002143893, my initial step would be to request the following in order to obtain the cookies for that specific order:</p><pre>https://orders.privateprogram.com/webapp/wcs/stores/servlet/MailOid?orderId=002143893&amp;mailId=a1c156c4–6c4a-4bf9–9a17–2c5bvcdf6ec1</pre><p>I will get a blank response, but the server will provide me with the cookies for that specific order.</p><pre>HTTP/1.1 200 Ok<br /><br />.<br />..<br />...<br /><br />Set-Cookie:WC_PERSISTENT*=*************************<br />Set-Cookie:WC_AUTHENTICATION_*=***********************<br />Set-Cookie:WC_USERACTIVITY_*=*************************<br /><br />...<br />..<br />.</pre><p>Now that I have the cookies, I can now access order <em>002143893</em></p><pre>https://orders.privateprogram.com/webapp/wcs/stores/servlet/OrderView?orderId=002143893</pre><p>This vulnerability could have allowed an attacker to access anyone’s order, comprising sensitive details such as Payment Method, Contract PDF, Billing &amp; Shipping Address, Email Address, Phone Number, First and Last Names, potentially exposing information of 3 Million People.</p><p>As you can see, Google Dorking and the Wayback Machine were the key to find this issue.</p><p>After the Security Team Investigation, they believed this vulnerability was never exploited.</p><h3><strong>Timeline:</strong></h3><blockquote><em>Reported → </em><strong>July 19th 2023</strong></blockquote><blockquote><em>Triaged → </em><strong>July 20th 2023</strong></blockquote><blockquote><em>Max Critical Bounty + Bonus Awarded → </em><strong>July 24th 2023</strong></blockquote><blockquote><em>Fixed → </em><strong>July 24th 2023</strong></blockquote><h3>NEXT:</h3><p><a href="https://medium.com/@bxmbn/i-received-a-bank-offer-in-my-mailbox-and-discovered-an-idor-vulnerability-5-000-bounty-bxmbn-5209cab1fba8">I received a Bank offer in my mailbox and discovered an IDOR vulnerability — $5,000 bounty — @bxmbn</a></p><img alt="" height="1" src="https://medium.com/_/stat?event=post.clientViewed&amp;referrerSource=full_rss&amp;postId=1096e6400e3d" width="1" />
