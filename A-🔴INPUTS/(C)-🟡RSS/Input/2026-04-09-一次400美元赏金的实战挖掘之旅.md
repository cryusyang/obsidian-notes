> 本文分享了一次通过自动化侦察、历史URL挖掘和人工验证，成功发现某大型电信运营商Swagger UI中反射型XSS漏洞的真实案例。漏洞源于`configUrl`参数未校验来源、无域名白名单且未净化远程JSON内容，导致可加载恶意配置并执行任意JS代码。作者复现了弹窗验证及伪造登录界面等利用方式，并探讨了窃取凭证、内网探测等扩展攻击场景。最后总结出Swagger UI易被忽视、历史数据是侦察金矿、自动化与人工结合是高效挖洞关键等核心经验。

  </span>
 </p>
 <h3 style="margin-top: 30px; margin-bottom: 15px; font-weight: bold; background-color: #000; color: #fff; padding: 2px 10px; width: fit-content; font-size: 17px; margin: 60px auto 10px;">
  <strong style="font-weight: bold; color: #fff;">

  </span>
  <strong style="font-weight: bold; color: black;">
   <span>

  </strong>
  <span>

  </span>
  <code>
   <span>
    configUrl
   </span>
  </code>
  <span>

  </span>
  <strong style="font-weight: bold; color: black;">
   <span>

   </span>
  </strong>
  <span>

  </span>
  <strong style="font-weight: bold; color: black;">
   <span>
    远程内容未净化
   </span>
  </strong>
  <span>

  </span>

 <p style="padding-top: 8px; padding-bottom: 8px; margin: 0; line-height: 26px; color: black; font-size: 14px;">
  <span>

  <span>
   <strong style="font-weight: bold; color: black;">
    <span>
     漏洞的深入利用方法与防护绕过技巧
    </span>
   </strong>
  </span>
 </h2>
 <p style="padding-top: 8px; padding-bottom: 8px; margin: 0; line-height: 26px; color: black; font-size: 14px;">
  <span>
   除了基础的XSS，这类配置注入漏洞还可能被用于更高级的攻击：
  </span>
 </p>
 <p style="padding-top: 8px; padding-bottom: 8px; margin: 0; line-height: 26px; color: black; font-size: 14px;">
  <strong style="font-weight: bold; color: black;">
   <span>
    1. 窃取敏感令牌与Cookie：
   </span>
  </strong>
  <span>
   攻击者可以构造恶意脚本，窃取当前用户的
  </span>
  <code>
   <span>
    document.cookie
   </span>
  </code>
  <span>
   、LocalStorage中的JWT令牌，或通过
  </span>
  <code>
   <span>
    fetch
   </span>
  </code>
  <span>
   API将敏感数据外传[2]。
  </span>
 </p>
 <p style="padding-top: 8px; padding-bottom: 8px; margin: 0; line-height: 26px; color: black; font-size: 14px;">
  <strong style="font-weight: bold; color: black;">
   <span>
    2. 发起内部网络探测（SSRF盲打）：
   </span>
  </strong>
  <span>
   利用受害者浏览器作为代理，访问并探测目标内网的API或管理界面（如
  </span>
  <code>
   <span>
    http://192.168.1.1/admin
   </span>
  </code>
  <span>
   ），并将响应结果回传到攻击者服务器。
  </span>
 </p>
 <p style="padding-top: 8px; padding-bottom: 8px; margin: 0; line-height: 26px; color: black; font-size: 14px;">
  <strong style="font-weight: bold; color: black;">
   <span>
    3. 组合其他漏洞进行提权：
   </span>
  </strong>
  <span>
   如果受害者是拥有更高权限的用户（如管理员），XSS漏洞可能成为其他攻击（如CSRF、权限提升）的跳板。
  </span>
 </p>
 <p style="padding-top: 8px; padding-bottom: 8px; margin: 0; line-height: 26px; color: black; font-size: 14px;">
  <strong style="font-weight: bold; color: black;">
   <span>
    4. 利用框架特性绕过内容安全策略：
   </span>
  </strong>
  <span>
   研究Swagger UI自身是否引入了某些宽松的CSP策略，或存在允许执行
  </span>
  <code>
   <span>
    eval()
   </span>
  </code>
  <span>
   等危险函数的情况，从而绕过常规的XSS防护。
  </span>
 </p>
 <h2 style="margin-top: 30px; margin-bottom: 15px; padding: 0px; font-size: 22px; text-align: center; font-weight: bold; color: black; line-height: 1.1em; padding-top: 12px; padding-bottom: 12px; margin: 70px 30px 30px; border: 1px solid #000;">
  <span>
   <strong style="font-weight: bold; color: black;">
    <span>
     核心收获与经验总结
    </span>
   </strong>
  </span>
 </h2>
 <p style="padding-top: 8px; padding-bottom: 8px; margin: 0; line-height: 26px; color: black; font-size: 14px;">
  <strong style="font-weight: bold; color: black;">
   <span>
    1️⃣ 被忽视的Swagger UI也可能成为安全短板
   </span>
  </strong>
  <span>
   开发与运维人员常常将Swagger UI视为无害的“文档页面”而忽视其安全配置。任何允许加载外部资源的参数都必须受到严格管控。
  </span>
 </p>
 <p style="padding-top: 8px; padding-bottom: 8px; margin: 0; line-height: 26px; color: black; font-size: 14px;">
  <strong style="font-weight: bold; color: black;">
   <span>
    2️⃣ 历史数据是侦察阶段的“金矿”
   </span>
  </strong>
  <span>
   利用Wayback Machine、Common Crawl等历史存档服务，配合
  </span>
  <code>
   <span>
    gau
   </span>
  </code>
  <span>
   、
  </span>
  <code>
   <span>
    katana
   </span>
  </code>
  <span>
   等现代化爬虫工具，可以系统性地发现那些不再被链接但仍可访问的“影子资产”[1]。
  </span>
 </p>
 <p style="padding-top: 8px; padding-bottom: 8px; margin: 0; line-height: 26px; color: black; font-size: 14px;">
  <strong style="font-weight: bold; color: black;">
   <span>
    3️⃣ “自动化广度扫描 + 人工深度验证”是最佳实践
   </span>
  </strong>
  <span>
   自动化工具（如
  </span>
  <code>
   <span>
    ffuf
   </span>
  </code>
  <span>
   ,
  </span>
  <code>
   <span>
    nuclei
   </span>
  </code>
  <span>
   ）负责快速地覆盖大量目标与常见漏洞模式；而安全研究员则专注于对可疑点进行深度分析、逻辑梳理和漏洞链构造，这是当前发现高质量漏洞的有效模式。
  </span>
 </p>
 <p style="padding-top: 8px; padding-bottom: 8px; margin: 0; line-height: 26px; color: black; font-size: 14px;">
  <strong style="font-weight: bold; color: black;">
   <span>
    4️⃣ 漏洞挖掘需要关注“非常规”参数
   </span>
  </strong>
  <span>
   除了常见的
  </span>
  <code>
   <span>
    q
   </span>
  </code>
  <span>
   、
  </span>
  <code>
   <span>
    search
   </span>
  </code>
  <span>
   、
  </span>
  <code>
   <span>
    redirect
   </span>
  </code>
  <span>
   等参数，应特别关注那些用于配置、调试、导入功能的参数，如
  </span>
  <code>
   <span>
    config
   </span>
  </code>
  <span>
   、
  </span>
  <code>
   <span>
    debug
   </span>
  </code>
  <span>
   、
  </span>
  <code>
   <span>
    load
   </span>
  </code>
  <span>
   、
  </span>
  <code>
   <span>
    importUrl
   </span>
  </code>
  <span>
   、
  </span>
  <code>
   <span>
    template
   </span>
  </code>
  <span>
   等，它们往往蕴含更高的风险。
  </span>
