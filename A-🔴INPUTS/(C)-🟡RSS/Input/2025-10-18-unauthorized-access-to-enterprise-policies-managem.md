<p>During beta testing of the <strong>Policies Management</strong> feature in CodeCollabHub, I discovered a <strong>Broken Access Control (BAC)</strong> vulnerability. Despite the official documentation stating that only <strong>admins</strong> should be able to create and manage policies, I was able to <strong>view, edit, and delete organization-wide policies as a non-admin user</strong>.</p><p>For this report, I received a <strong>$500 bounty</strong>.</p><figure><img alt="" src="https://cdn-images-1.medium.com/max/1024/1*8ts_rjmTzK3yo6viexN_Sg.png" /></figure><h3>Understanding the Target</h3><p>CodeCollabHub is a cloud-based collaboration platform that provides secure project hosting, package management, and organizational controls.</p><p>The <strong>Policies Management feature</strong> is designed to enforce:</p><ul><li>Package usage restrictions (e.g., only MIT-licensed dependencies).</li><li>Repository access rules.</li><li>Security compliance across projects.</li></ul><p>According to official documentation, <strong>only administrators</strong> are allowed to create, edit, or delete these policies. Regular project members (like developers or contributors) should only be able to view policies relevant to their projects.</p><p>However, while exploring the application, I noticed there was <strong>no visible “create policy” option in the UI</strong> for my non-admin test account. That’s when I switched gears and decided to dig deeper.</p><h3>The Flaw: Hidden Endpoint &amp; Access Control Bypass</h3><p>I scraped JavaScript files and noticed references to /ui/Policies. Accessing this endpoint directly revealed the hidden <strong>Policies Management dashboard</strong>.</p><p>As a non-admin user, I was able to:</p><ul><li><strong>View all policies</strong>, even those created by other users.</li><li><strong>Create new policies</strong> despite lacking admin privileges.</li><li><strong>Edit and delete existing policies</strong>, including ones belonging to other projects.</li></ul><p>This indicated that while the <strong>UI restricted access</strong>, the <strong>backend API failed to enforce role-based authorization</strong>, leading to a complete privilege escalation.</p><h3>Steps to Reproduce</h3><p><em>Log in as a non-admin user.</em></p><p><em>Navigate to </em><a href="https://codecollabhub.com/ui/Policies"><em>https://codecollabhub.com/ui/Policies</em></a></p><p><em>Observe that all organization-wide policies are visible.</em></p><p><em>Attempt to edit or delete an existing policy belonging to another user.</em></p><p><em>Confirm that the change is successfully applied, bypassing the admin-only restriction.</em></p><h3>Impact</h3><ul><li><strong>Privilege Escalation:</strong> Non-admins could act as admins in policy management.</li><li><strong>Data Integrity Risks:</strong> Malicious users could weaken security by modifying enforcement rules.</li><li><strong>Denial of Service:</strong> Deleting all policies could disrupt compliance across all projects.</li><li><strong>Supply Chain Attacks:</strong> Attackers could alter dependency policies to allow insecure or malicious packages.</li></ul><h3>Timeline</h3><ul><li><strong>Feb 21, 2025</strong> — Report <strong>Medium (6.0)</strong>.</li><li><strong>Feb 2025 (v6.8.3 release)</strong> — Fix deployed.</li></ul><figure><img alt=""
