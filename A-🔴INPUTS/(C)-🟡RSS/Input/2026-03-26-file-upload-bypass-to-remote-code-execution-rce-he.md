<h3>Introduction</h3><p>Hello everyone,</p><p>I’m Aland Dlshad, also known as HexaPHP. I’m a cybersecurity specialist focused on web application penetration testing and vulnerability research.</p><p>In this write-up, I present the discovery of a critical Remote Code Execution (RCE) vulnerability in a file upload functionality. The issue was caused by insufficient validation of uploaded files, allowing manipulation of filenames and paths. By combining a double extension technique with path traversal, it was possible to bypass restrictions and upload a malicious file to an unintended location, ultimately leading to full system compromise.</p><h3>Discovery Process</h3><p>The assessment began by registering a normal user account. At first glance, the application appeared to function as expected, with no obvious vulnerabilities.</p><p>While exploring the features, attention was drawn to the profile section, where users were allowed to upload a profile picture. This functionality became the primary target for testing.</p><figure><img alt="" src="https://cdn-images-1.medium.com/max/1024/1*CSdtpmMgGvsA1JiyClO0dg.png" /></figure><p>As an initial step, a standard image file was uploaded using:</p><pre>filename=&quot;11.png&quot;</pre><figure><img alt="" src="https://cdn-images-1.medium.com/max/1024/1*P_gZA9j9L6iRUcOP66zpAw.png" /></figure><p>The upload succeeded without restrictions. Afterward, the file path was identified, confirming that uploaded files were stored and accessible within the same domain. This indicated that user-controlled files could potentially be accessed directly via the web.</p><h3>Initial Testing</h3><p>To evaluate the robustness of the upload validation, the filename was modified to:</p><pre>filename=&quot;11.php&quot;</pre><p>Although the file upload was accepted, it did not execute as PHP code. This suggested that some level of filtering or handling was in place, but not comprehensive enough.</p><p>Multiple bypass attempts were performed, including variations in extensions and encoding techniques however, these attempts did not initially succeed.</p><h3>Bypassing File Upload Restrictions</h3><p>Further testing focused on manipulating both the filename and the request headers.</p><p>In the final attempt, the upload request was modified as follows:</p><p>Changed the Content-Type to:</p><pre>application/x-php</pre><p>Modified the filename to:</p><pre>../11.png.php</pre><figure><img alt="" src="https://cdn-images-1.medium.com/max/1024/1*blujupJ5kjY-sY7KTOWIJQ.png" /></figure><p>This payload combined two important techniques:</p><ul><li><strong>Double Extension</strong> (.png.php) to bypass extension filtering</li><li><strong>Directory Traversal</strong> (../) to move one level back from the intended upload directory</li></ul><p>The upload was successful, confirming that the validation mechanism could be bypassed and that files could be written outside the designated directory.</p><figure><img alt="" src="https://cdn-images-1.medium.com/max/1024/1*XEc2AA6BuZyYY_l-Ma97QA.png" /></figure><figure><img alt="" src="https://cdn-images-1.medium.com/max/1024/1*vwCps4JHFJfufhH1eC-WSg.png" /></figure><h3>Conclusion</h3><p>This vulnerability demonstrates the risks associated with improper file upload validation. Relying solely on client-controlled attributes such as filename or content type is insufficient and can be easily bypassed.</p><p>To mitigate such issues, developers should:</p><ul><li>Enforce strict server-side validation and file type whitelisting</li><li>Sanitize and normalize filenames</li><li>Store uploaded files outside the web root</li><li>Rename files to prevent user-controlled naming</li><li>Disable execution permissions in upload directories</li></ul><p>Implementing these controls is essential to prevent exploitation and ensure the security of web applications.</p><h3>Contact</h3><p>If you’d like to connect or learn more about my work:<br /> <a href="https://hexaphp.com/"><strong>https://hexaphp.com</strong></a></p><img alt="" height="1" src="https://medium.com/_/stat?event=post.clientViewed&amp;referrerSource=full_rss&amp;postId=cbb7e5f09175" width="1" />
