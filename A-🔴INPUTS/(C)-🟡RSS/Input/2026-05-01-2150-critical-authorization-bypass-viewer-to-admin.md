> [!example] AI 摘要
> 该文章描述了一次在SaaS平台ExampleCenter中发现的关键性越权漏洞：低权限用户通过直接调用未做权限校验的API接口（/api/calendar/v2/permissions/{id}），成功将自身权限从“日历查看者”提升为“日历管理员”，实现完全权限接管。漏洞根源在于后端API缺失授权检查，仅依赖前端UI隐藏功能，导致认证用户可任意修改权限配置。该问题被评定为高危（CVSS最终评级为High），作者因此获得2000美元赏金及150美元复测奖金，厂商已修复。

<p>Hi Everyone! While testing a SaaS platform (let’s call it <strong>ExampleCenter</strong>), I discovered a <strong>critical Broken Access Control vulnerability</strong> that allowed a low-privileged user to escalate from a <strong>Calendar Viewer → Calendar Administrator</strong> using a simple API request.</p><p>For this finding, I was awarded a <strong>$2,000 bounty + $150 retest bonus</strong>.</p><p>This is one of those bugs where everything looks perfectly secure from the UI… but completely breaks at the backend. Let’s walk through how I found it.</p><figure><img alt="" src="https://cdn-images-1.medium.com/max/1024/1*TV9d8X9NQ7jcgKrhBZ9qNg.png" /></figure><h3>Understanding the Target</h3><p>ExampleCenter provides a <strong>calendar management system</strong> where organizations manage:</p><ul><li>Events</li><li>Rooms &amp; resources</li><li>People scheduling</li><li>Conflict resolution</li></ul><p>The permission model is clearly defined:</p><ul><li><strong>Viewer</strong> → Read-only access</li><li>Editor -&gt; Limited edit and manage resources permissions</li><li><strong>Administrator</strong> → Full control over calendar</li></ul><p>From a Viewer account, I verified:</p><ul><li>❌ Cannot edit rooms</li><li>❌ Cannot manage resources</li><li>❌ Cannot access permission settings</li></ul><p>So far, everything looked correctly restricted.</p><h3>The Thought That Changed Everything</h3><p>While testing, I noticed something important:</p><p>👉 The UI completely hides permission management for non-admin users</p><p>But from experience, I’ve learned:</p><blockquote><em>If the UI hides something… it doesn’t mean the API is protected</em></blockquote><p>So I asked myself:</p><p>👉 <em>What if I directly hit the permission API?</em></p><h3>The Flaw: Full Privilege Escalation via API</h3><p>I intercepted a request related to permissions from admin account and modified it while logged in as a <strong>Viewer and use it</strong>.</p><h4>Crafted Request</h4><pre>PATCH /api/calendar/v2/permissions/{my_user_id} HTTP/2<br />Host: api.examplecenter.com<br />Authorization: Bearer &lt;viewer_token&gt;<br />Content-Type: application/json<br /><br />{<br />  &quot;data&quot;: {<br />    &quot;type&quot;: &quot;PersonPermissions&quot;,<br />    &quot;attributes&quot;: {<br />      &quot;permissions_level&quot;: &quot;Administrator&quot;,<br />      &quot;product_permissions&quot;: {<br />        &quot;editRooms&quot;: true,<br />        &quot;editResources&quot;: true,<br />        &quot;editPeople&quot;: true,<br />        &quot;resolvesConflicts&quot;: true<br />      }<br />    }<br />  }<br />}</pre><h3>What I Expected vs What Happened</h3><h4>Expected</h4><p>❌ 403 Forbidden</p><p>❌ Unauthorized action</p><h4>Actual</h4><p>👉 <strong>200 OK</strong></p><p>And after refreshing the UI…</p><p>👉 I was now a <strong>Calendar Administrator</strong></p><h3>What Access Did I Get?</h3><p>After escalation, I gained full control over the calender system:</p><ul><li>✅ Manage rooms</li><li>✅ Manage resources</li><li>✅ Edit people permissions</li><li>✅ Resolve conflicts</li><li>✅ Modify calendar settings</li></ul><p>This wasn’t partial access —</p><p>👉 <strong>This was full administrative takeover of the calendar system</strong></p><h3>Root Cause</h3><p>This vulnerability existed because:</p><blockquote><strong><em>Authorization checks were implemented only in the UI, not in the backend API</em></strong></blockquote><p>The endpoint: /api/calendar/v2/permissions/{id}</p><p>Did NOT validate:</p><ul><li>User role</li><li>Permission boundaries</li><li>Authorization to modify permissions</li></ul><p>👉 Any authenticated user could modify their own permission object</p><h3>Impact</h3><p>This is a textbook <strong>critical privilege escalation</strong>:</p><h4>Security Impact</h4><ul><li>Viewer → Administrator escalation</li><li>Full control over calendar system</li><li>Ability to modify permissions of others</li></ul><h4>Operational Impact</h4><ul><li>Manipulate or delete events</li><li>Disrupt scheduling workflows</li><li>Abuse conflict resolution</li></ul><h4>Business Risk</h4><ul><li>Complete breakdown of permission model</li><li>Unauthorized administrative control</li><li>Potential internal misuse or disruption</li></ul><h3>Bounty &amp; Program Response</h3><ul><li><strong>Reported:</strong> Jan 16, 2026</li><li><strong>Triaged:</strong> Jan 20, 2026</li><li><strong>Severity:</strong> Critical → High (final CVSS classification)</li><li><strong>Bounty:</strong> $2,000 + $150 retest bonus</li><li><strong>Retest:</strong> Fix confirmed (API now properly returns 403)</li></ul><figure><img alt="" src="https://cdn-images-1.medium.com/max/1024/1*G22-HjF5Du9PsPtagpCcVA.png" /></figure><h3>Key Takeaways</h3><ul><li>Never trust UI-based restrictions — always test backend APIs</li><li>Permission endpoints are <strong>high-value targets</strong></li><li>Always test: Role upgrades, Self-permission changes, Hidden admin endpoints</li><li>If you can modify your own permission object → <strong>it’s game over</strong></li><li>Always compare: What UI allows and What API allows</li></ul><h3>Personal Insight</h3><p>This bug came from a very simple question:</p><blockquote><em>“Can I modify my own permissions directly?”</em></blockquote><p>Sometimes the most critical bugs don’t come from complex techniques —</p><p>they come from testing <strong>basic assumptions properly</strong>.</p><h3>Conclusion</h3><p>This vulnerability highlights a critical flaw in many SaaS applications:</p><p>👉 <strong>Mismatch between frontend restrictions and backend authorization</strong></p><p>Even though the UI correctly restricted access, the backend API allowed full privilege escalation — completely breaking the security model.</p><p>As a hunter, always remember:</p><blockquote><em>The UI is just a suggestion — the API is the truth.</em></blockquote><p>Until next time — happy hacking! 🚀</p><h3>Connect and Engage</h3><p>💬 What’s your experience
